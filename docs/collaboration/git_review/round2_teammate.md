# 2라운드: 팀원 (초보 가정)

> 가정은 1라운드와 같습니다(add·commit·push만 해 본 팀원, 다른 과목 과제 많음). 실제 숙련도는 모릅니다.

## 1. 다른 검토자 의견에 대한 동의와 반박

- **교수**: 이메일 미연결이 가장 급하다는 지적(문제 1)과, 날짜를 고치지 말고 소급 표시만 하자는 의견에 동의합니다. 보완할 점은 "고칠 점은 리뷰 반영 커밋으로"(4장 가.3)입니다. 이렇게 하면 초보가 첫날 남의 브랜치에 push해야 합니다. 리뷰 화면의 Suggest changes를 쓰면 웹에서 끝나고, 주인이 적용하면 제안자가 공동 작성자로 들어갑니다[1]. "분야 지도를 팀원 커밋으로"는 만든 사람이 팀원일 때만 맞습니다. 04에는 "아이디어를 낸 팀원"뿐이라 확인이 필요합니다.
- **엔지니어**: 합치기 전 이메일 정리, "작성자는 사람, Claude는 Co-Authored-By에만", 오타는 이슈 없이 PR, 문서 PR에서 실행 리뷰 빼기, "작은 문서로 사이클 한 번 같이"에 동의합니다. enforce_admins 켜기에는 반대합니다. 시험 기간에 내가 응답 못 하면 주인 작업까지 막혀 부담이 나에게 몰립니다. 끄고 두되 "24시간 무응답일 때만 건너뛰고 PR에 이유 한 줄"을 규칙으로 두기를 권합니다.
- **GPT**: squash 이유를 커밋 수로 적지 말 것, 마감 뒤 허용 범위는 공지대로 "README와 발표 자료"만(용어 데이터는 기능), "팀이 판단" 표현은 실제 결정자가 확인할 것에 동의합니다. 버린 사전 시험을 합칠 의무가 없다는 의견에는 반대합니다. 기본 브랜치에 들어가야 기여로 잡히므로[2] 1주차 내 일이 버려진 시험 하나면 그 주 기록이 사라집니다.

## 2. 쟁점별 최종 입장

1) **브랜치**: A를 유지합니다. C에서는 `spike/`와 기능 동결 규칙만 가져옵니다. 필수 태그는 `v1.0` 하나이고, 주차 태그와 Release는 선택입니다.
2) **버린 사전 시험**: 두 시험 모두 `experiments/<이름>/`에 결과 README와 핵심 코드만 합칩니다. 어느 쪽이 버려져도 같게 다룹니다.
3) **squash 이유**: "작업 단위와 검토 이력 보존"으로 적습니다. 커밋 수로 적으면 억지 쪼개기와 커밋 수 경쟁이 생깁니다. Contributors 그래프가 merge commit을 세지 않는다는 점[3]도 한 줄 넣습니다.
4) **마감**: 공식 기준은 "12/20 23:59까지 main 합치기 완료"입니다. 내부 마감은 기능 PR 열기 12/19(토) 18:00, 기능 합치기 12/20 18:00, 버그 합치기 22:00, `v1.0` 23:00입니다. 리뷰 응답은 24시간, 마감 주에는 12시간으로 둡니다.
5) **PR #3**: 쪼개지 않고 범위를 좁혀 리뷰합니다. 쪼개면 주인 이름의 PR만 늘고, 나는 같은 내용을 두 번 봅니다. PR 본문에 세 가지를 추가합니다.
   - 소급 표시: "11/17~19 작업을 11/19에 한꺼번에 올림".
   - 리뷰 범위: 꼭 볼 것은 `04`(101줄), `05`(28줄), `README`(60줄)로 약 190줄입니다. 훑을 것은 `01`~`03`입니다. 심사위원 원문 3개(643줄)는 이름, 학번, 경로만 검색합니다.
   - "내가 한 말" 항목: 내가 참여한 부분에만 답합니다.
6) **팀원 기여 0**: 지난 기록을 내 몫으로 돌리지 않고, 앞으로의 몫을 첫 주에 만듭니다.
   - 첫날: PR #4 리뷰(줄 코멘트 2~3개와 Approve)[2], PR #3 범위 리뷰(Suggest changes)[1].
   - 2~3일 안: 02·05의 "팀이"를 사람별로 고치는 작은 PR을 내가 직접 냅니다. 누가 말했는지는 사람만 아는 사실이라 내용 있는 기여이고, 첫 사이클 연습도 됩니다. 내가 빠진 판단은 "주인"으로 적습니다.
   - 1주차: 주제 결정 이슈에 내 한 문장 정의를 댓글로 남기고, 사전 시험 하나를 이슈→`spike/`→PR까지 맡습니다.
   - 분야 지도는 만든 사람이 직접 커밋합니다.
7) **이메일**: (가)를 권합니다. "둘 다 noreply" 한 규칙이 되어 CONTRIBUTING 7장과 맞기 때문입니다. 조건은 셋입니다.
   - 팀원 초대 **전에** 끝냅니다. 내가 브랜치를 받은 뒤 force push하면 초보는 어긋난 저장소를 풀지 못합니다.
   - `--reset-author`는 작성 시각까지 바꾸므로 쓰지 않습니다[4]. Co-Authored-By는 남깁니다.
   - 예전 커밋이 PR의 force-push 기록에 남는지는 확인이 필요합니다.
   - 노출을 개의치 않으면 force push가 없는 (나)가 더 안전합니다(예전 커밋 재연결 여부는 확인 필요).
8) **작성자 규칙**: 작성자는 사람이고, Claude는 Co-Authored-By에만 둡니다. 다른 AI 도구를 쓰면 PR 양식 "AI 사용" 칸에 적습니다. AI가 자기 계정으로 커밋하거나 PR을 여는 기능은 쓰지 않습니다.
9) **1주차 장치**: PR 양식 1개(무엇을, 어떻게 확인, AI 사용과 틀린 점), 이슈 양식 1개(목적, 완료 조건, 담당자), 겹치는 기본 라벨 정리, `.gitignore`. 영역 라벨, CODEOWNERS, Actions는 넣지 않습니다.

## 3. 1라운드에서 고칠 내 주장
- **이메일 미연결을 놓쳤습니다.** "기록이 lumos0107에게 쌓였다"는 이슈와 PR에만 맞습니다. 커밋 7개는 누구의 기여로도 잡히지 않습니다.
- 이슈 양식은 2개에서 1개로 줄입니다. 주차 태그는 필수에서 선택으로 내립니다.
- "마지막 코드 PR 12/19"는 위 4)의 합치기 완료 기준 시각표로 바꿉니다.
- "Merge 버튼은 기여 숫자를 늘리지 않는다"는 Insights 그래프에 한정합니다. 프로필 기준은 확인하지 못했습니다.
