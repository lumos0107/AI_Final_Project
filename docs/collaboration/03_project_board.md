## 2. 구성

### 가. 카드

1) 카드 하나가 이슈 하나입니다.
2) PR은 카드로 따로 올리지 않습니다. 이슈 카드에 연결된 PR 번호가 함께 보입니다.

### 나. 단계

| 단계 | 뜻 |
|---|---|
| Todo | 아직 시작하지 않은 일 |
| In Progress | 브랜치를 만들어 작업 중이거나 PR 리뷰 중인 일 |
| Done | 이슈가 닫힌 일 |

리뷰 중 단계를 따로 두지 않은 이유는 2명이라 PR이 한두 개뿐이고, 리뷰 상태는 이슈 카드에 연결된 PR에서 보이기 때문입니다.

### 다. 화면

1) 보드: 단계별 세 칸입니다.
2) 전체 목록: 표로 봅니다. 칸은 제목, 단계, 담당자, 라벨, 마일스톤, 연결된 PR입니다.

### 라. 자동 규칙

1) 보드를 만들 때 켜져 있던 규칙은 6개입니다(11/24 API 조회).
   - Item closed: 이슈나 PR이 닫히면 Done으로 바꿉니다.
   - Pull request merged: PR이 합쳐지면 Done으로 바꿉니다.
   - Item added to project: 카드가 추가될 때 단계를 정합니다.
   - Pull request linked to issue: 이슈에 PR이 연결될 때 이슈 카드의 단계를 바꿉니다.
   - Auto-close issue: 카드가 정해진 단계로 바뀌면 이슈를 닫습니다.
   - Auto-add sub-issues to project: 하위 이슈를 보드에 함께 올립니다.
2) 앞의 두 개는 깃허브 문서에 적힌 기본 동작입니다. 나머지 네 개가 어떤 단계로 바꾸는지는 보드의 Workflows 메뉴에서 확인합니다.
3) 새 이슈를 보드에 자동으로 올리는 규칙(Auto-add to project)은 켜져 있지 않습니다. 이 규칙은 깃허브 웹 화면에서만 켤 수 있습니다.

## 4. 쓰는 법

1. 이슈를 만들 때 오른쪽 Projects에서 "AI_Final_Project 작업 보드"를 고릅니다. 자동 추가 규칙을 켜면 이 단계는 필요 없습니다.
2. 브랜치를 만들어 작업을 시작하면 카드를 In Progress로 옮깁니다.
3. PR이 합쳐지거나 이슈가 닫히면 카드는 자동으로 Done으로 갑니다.
4. 보드에서 카드를 직접 Done으로 옮기면 Auto-close issue 규칙 때문에 이슈도 닫힐 수 있습니다. 일이 끝났을 때만 옮깁니다.
